# v1.1.0 Architecture and Test Hardening

## Purpose

SonicTerm sometimes leaves stale or overlapping Vim content because the hardware renderer retains prior pixels and limits repainting to dirty-row damage. The v1.1.0 work also closes concrete release, panic-safety, and deterministic-test gaps found by a full 22-crate audit.

## Architecture decision

The current architecture remains in place. Its dependency graph is acyclic and its ownership is coherent:

```text
platform shell -> sonicterm-app -> VT/grid -> render-model -> GPU
                                      ^                         |
                                      |                         v
                                  IO / mux                     UI
```

GPU access to grid/config/UI remains behind render-model; mux continues through the IO PTY seam; platform crates remain thin. This release fixes localized defects rather than redesigning working boundaries.

## Required behavior

1. A dirty alternate-screen pane repaints its complete clipped pane rectangle. Normal shell panes retain narrow dirty-row damage. Partial rendering is not disabled globally.
2. VT/grid tests prove same-frame dirty propagation for alternate-screen entry/exit, DECSTBM scrolling, IL/DL, RI, CSI S/T, ED/EL, resize, and wide-cell edits.
3. Variable-font metadata failure in `weight_and_width` degrades to base OS/2/default metrics and cannot abort the release build.
4. Material deterministic behavior identified by the audit receives branch and edge-case unit coverage, including app-core state/effect contracts, URL safety, render geometry/damage, grid line behavior, UI copy mode, config/theme helpers, font value/parser helpers, and mux protocol messages.
5. The Rust logic coverage gate measures its intended deterministic surface, including app-core and font-config, at 80% or higher.
6. Workspace metadata and internal dependency requirements resolve consistently at 1.1.0. The existing render-model `MIT OR Apache-2.0` license remains unchanged.
7. Busy torn-out windows cannot deadlock during close: VT workers post typed redraw events carrying `WindowId`, and only the winit event-loop thread calls native window redraw APIs. The Windows software-render production path remains equivalent to v1.0.1.

## Testing policy

Unit tests use flat `<file>_tests.rs` siblings declared from their source module. `tests/` is reserved for genuine cross-crate/public-API integration.

Generated/native FFI, real PTYs and SSH, wgpu surfaces, AppKit, Win32, and winit event-loop behavior are not represented by hollow unit tests. Their substitutes are link/build gates, existing integration suites, macOS manual launch/Vim verification, Windows CI, installer builds, and release asset checks.

## Acceptance

- A deterministic regression proves normal-screen row damage remains narrow while alternate-screen dirty damage expands to the full pane.
- Targeted VT/grid tests prove the mutation families above mark every affected row before a frame is consumed.
- The variable-font failure path is checked and its pure axis-scaling behavior is unit-tested.
- Formatting, clippy with warnings denied, workspace unit/bin tests, per-crate tests, corrected coverage (at least 80%), release-note tests, and the macOS release build all pass.
- The release app is exercised with Vim/nvim through rapid scrolling, edits, splits, resizing, search, shell/suspend return, and alternate-screen transitions without stale content.
- A macOS release-build smoke repeatedly closes a torn-out window with at least two continuously producing panes under a two-second timeout; no freeze or redraw-target wait cycle occurs, remaining windows stay responsive, and pane processes are reaped.
- The Windows software renderer and presenter retain v1.0.1 production semantics; source parity plus focused software-render tests are release evidence.
- GitHub macOS and Windows checks pass on the single consolidated PR.

## Non-goals

- No crate-boundary or public-API redesign.
- No unconditional full-window repaint.
- No dependency upgrade.
- No broad app-module refactor.
- No tests whose only purpose is checking derives, getters, or exports.
- No tag, release publication, merge, or milestone closure without a later explicit owner instruction.
