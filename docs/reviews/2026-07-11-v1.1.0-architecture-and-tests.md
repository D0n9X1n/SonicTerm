# v1.1.0 Architecture and Unit-Test Audit

## Verdict

SonicTerm's workspace architecture is reasonable and should be retained. The 22-crate dependency graph is acyclic, responsibilities are cohesive, and communication uses typed data and bounded seams. The audit found localized correctness, release-hygiene, and test-coverage gaps—not a need for architectural churn.

## Component and communication review

| Area | Verdict |
| --- | --- |
| Platform entry points | `sonicterm-mac` and `sonicterm-windows` remain thin binary/glue crates. Cross-platform behavior is owned by app or lower crates. |
| App boundary | `sonicterm-app-core` owns pure intent/state/effect contracts; `sonicterm-app` owns winit orchestration, windows, tabs, panes, and redraw scheduling. |
| Terminal state | PTY bytes flow through `sonicterm-vt` into `sonicterm-grid`; grid owns cells, scrollback, wide-cell repair, and dirty rows. |
| Rendering | `sonicterm-render-model` is the declared grid/UI-to-GPU seam. `sonicterm-gpu` does not directly depend on grid/cfg/UI packages. |
| Text/font | Text caching/atlas concerns and font discovery/shaping/rasterization remain separated. Native FFI is isolated in wrapper crates. |
| IO and mux | GUI and mux PTYs share `sonicterm-io`; mux owns framing/subscription rather than a second process implementation. |
| Concurrency | Crossbeam channels, atomics, and short parser/grid critical sections are used appropriately. Renderer access is non-blocking; PTY writes occur outside parser locks. |
| Public contracts | Shared value contracts remain in `sonicterm-types`; renderer-specific GPU values stay downstream. |
| Error handling | Most native boundaries propagate errors. The variable-font metadata unwrap was the verified panic-safety exception selected for repair. |

## Crate responsibility matrix

| Crate | Responsibility and communication boundary |
| --- | --- |
| `sonicterm-types` | Backend-free shared value contracts and trait seams consumed across the workspace. |
| `sonicterm-vt` | Parses PTY byte streams and applies terminal protocol mutations to `sonicterm-grid`. |
| `sonicterm-grid` | Owns cells, lines, scrollback, wide-cell repair, hyperlinks, revisions, and dirty rows. |
| `sonicterm-cfg` | Owns config/theme/keymap parsing, assets, dimensions, URL scanning, and safe-open policy. |
| `sonicterm-io` | Isolates PTY, process, locale, shell-startup, and optional SSH IO from app/UI layers. |
| `sonicterm-text` | Owns renderer-neutral glyph atlas data, shaping helpers, and row glyph caches. |
| `sonicterm-font` | Owns discovery, fallback, shaping, FreeType/DirectWrite rasterization, and safe native wrappers. |
| `sonicterm-font-config` | Defines font configuration values shared by the font stack and engine seam. |
| `sonicterm-freetype` | Exposes generated FreeType ABI bindings and deterministic fixed-point helpers. |
| `sonicterm-harfbuzz` | Exposes generated HarfBuzz ABI bindings; safe shaping policy stays in `sonicterm-font`. |
| `sonicterm-fontconfig` | Exposes generated Fontconfig ABI bindings for non-macOS discovery. |
| `sonicterm-engine` | Provides the narrow `FontStack` and cell-metrics seam used by rendering code. |
| `sonicterm-block-glyph` | Owns Sonic-adapted box/block/Powerline/Braille geometry and raster glue. |
| `sonicterm-render-model` | Declares renderer-neutral frame, pane, geometry, and grid/cfg/UI boundary data. |
| `sonicterm-ui` | Computes renderer-neutral tabs, palette, search, selection, IME, copy-mode, and scrollbar state. |
| `sonicterm-gpu` | Consumes render-model data and emits wgpu quads/glyph draws; native surfaces stay internal. |
| `sonicterm-app-core` | Owns the winit-free reducer, intents, durable app state, effects, and ordering contracts. |
| `sonicterm-app` | Translates app-core contracts into windows, panes, PTYs, input, redraws, and platform-shell actions. |
| `sonicterm-mac` | Supplies the macOS binary and AppKit menu/drag/window glue while delegating cross-platform behavior. |
| `sonicterm-windows` | Supplies the Windows binary, ConPTY/Win32 chrome and drag glue, software presenter, and WiX metadata. |
| `sonicterm-mux` | Owns persistent-session framing/subscription and reuses the `sonicterm-io` PTY seam. |
| `sonicterm-logging` | Owns logging config, sinks, retention, panic/crash reporting, paths, and exit tracing. |

## Audit work items

1. Alternate-screen retained-pixel correctness: full-pane damage for dirty Vim/TUI panes while normal shells keep narrow damage.
2. Manifest normalization: consistent workspace version/MSRV/lints without changing render-model's dual license.
3. Variable-font metadata failure: non-fatal fallback in an infallible query.
4. App-core tests: reducer transitions, effect ordering, and cascade behavior.
5. Coverage tooling: eliminate prefix over-exclusion of app-core and font-config and measure deterministic logic honestly.
6. URL safety: scanner and open-policy unit coverage.
7. Deterministic terminal/render tests: grid line and dirty behavior, render geometry, color, and shared helper contracts.
8. Deterministic UI/config/font/mux tests: copy-mode, theme/value helpers, parser/range helpers, and protocol round trips.
9. Test ownership: flat sibling unit tests; integration directories reserved for true integration.
10. v1.1.0 workspace version and release documentation.
11. Torn-out-window close safety: typed redraw handoff to the event-loop thread, deterministic lock-release regression, lifecycle verification, and macOS busy-close smoke.
12. Windows software rendering: preserve v1.0.1 production behavior while retaining current focused presenter/rasterizer tests.

## Unit-test posture by crate

| Crate group | Unit-test focus | Native/integration substitute |
| --- | --- | --- |
| types, app-core, cfg, grid, render-model, UI | Pure contracts, transitions, parsing, geometry, dirty/wide invariants | Workspace and per-crate gates |
| VT | Escape-sequence replay and same-frame state mutation | Existing VT↔grid integration suites |
| GPU | CPU-constructable damage/color/cache geometry | Real wgpu surface via macOS launch and Windows CI |
| font-config, font helpers, engine | Pure values, ranges, parser helpers, metrics decisions | Native font stack release build |
| text | Shape/cache helpers that do not require a platform font | Font/GPU integration in release app |
| IO, mux | Pure parsing/framing and PTY helper policy | Existing real-process tests and platform CI |
| freetype, harfbuzz, fontconfig | Fixed-point/helper code only | C link/build plus consuming font-stack tests |
| mac, windows | Host-independent parsing only | App launch, DMG/MSI jobs, platform CI |
| logging | Config/path/retention helpers | Panic/exit/file integration behavior |
| block-glyph | Sonic glue contracts only | Render-path smoke; vendored geometry is not duplicated in low-value tests |

## Explicit exceptions

The following cannot be honestly guaranteed by unit tests alone:

- swapchain acquisition, retained texture, scissor execution, and presentation;
- real PTY child lifecycle, terminal driver behavior, and SSH sockets;
- AppKit/Win32/OLE/DWM/winit window and input handles;
- generated C bindings and native FreeType/HarfBuzz/Fontconfig behavior;
- installer signing and package installation.

Their required checks are compilation/linking, existing integration tests, macOS release launch and manual Vim verification, the torn-out two-pane busy-close smoke with post-close responsiveness and process-reap checks, GitHub macOS/Windows checks, DMG/MSI builds, binary-architecture checks, and checksum generation. The Windows software-render production files are also compared directly with v1.0.1; only flat sibling test-module relocation may differ without additional behavioral evidence.

## Verified release evidence

- The owner completed the macOS release-build torn-out busy-window exercise and reported the close path remained responsive with no visible freeze.
- The isolated test process exited with zero remaining windows, no `ST825_LEFT`/`ST825_RIGHT` processes, and its shell child reaped. The log recorded `child window reaped after drag-merge; remaining children=0` and no panic, deadlock, or error.
- Both main and child VT workers contain two typed `RequestRedraw(WindowId)` sends (buffer-threshold and timeout flushes) and zero native `request_redraw()` calls. The flat `redraw_target_tests.rs` unit regression covers main and child targets; its instrumented callback reacquires and clears the same target mutex, proving the guard is released before redraw dispatch.
- Workspace tests, the per-crate gate, clippy with warnings denied, release-note tests, and the macOS release build pass.
- Corrected deterministic line coverage is 83.00% (4,648 measured lines, 790 missed), above the unchanged 80% threshold.
- The Windows software rasterizer and presenter have no material production-source delta from v1.0.1; focused presenter selection, dirty-rect, pixel-fill, and rasterizer tests pass.
- Stable workspace `cargo fmt --all -- --check` still reports repository-wide formatting drift that also reproduces from an untouched `HEAD` archive; `git diff --check` and focused formatting of changed files are clean. This inherited baseline is not represented as a passing gate.

## Release gate

```bash
cargo fmt --all -- --check
cargo clippy --workspace --all-targets -- -D warnings
cargo metadata --no-deps --format-version 1
cargo test --workspace --lib --bins
bash scripts/check-workspace-crates.sh
scripts/coverage/rust-logic.sh
bash scripts/test-release-notes.sh
cargo build --release -p sonicterm-mac
```

No release is created by this audit. SonicTerm releases remain tag-driven and owner-gated.
